# AI 智能工具箱系统 · 项目介绍

## 一、项目概述

### 1.1 一句话定位

一套基于 **AI Agent 编排**的一体化生产力工具平台：用户用自然语言描述需求，系统自动判断意图、编排并执行一条由多个 AI 工具组成的流水线（DAG），并支持 cron 定时无人值守执行。

### 1.2 解决的核心问题

传统 AI 工具的问题是「功能割裂、需要逐个手动操作」。这个系统把「用工具」变成「说需求」——用户说一句「记录会议、生成纪要约张三」，系统自动完成：录音转写 → 生成纪要 → 提取待办 → 写入待办列表，全程无需手动在多个工具间切换。

### 1.3 核心特性

| 特性 | 说明 |
|---|---|
| 🤖 AI Assistant | 双模型意图识别，自动判断单工具 / 多步骤任务 |
| 🔀 智能工作流 | 自然语言自动生成工作流，DAG 画布拖拽编排 |
| ⏰ 定时智能体 | 按 cron 调度无人值守自动执行 AI 工作流 |
| 🧩 技能系统 | 文件夹式技能包（方法论 + 默认流程），可自定义扩展 |
| 🧠 自训练模型 | 3 个 DistilBERT 微调模型 + 1 个 FCN + 7 个 sklearn 模型 |

### 1.4 技术栈

| 层 | 技术 |
|---|---|
| 前端 | React 19 + TypeScript + Ant Design 6 + Vite |
| 后端 | FastAPI + SQLAlchemy + SQLite + APScheduler |
| 深度学习 | PyTorch + HuggingFace Transformers（Apple MPS 加速） |
| 经典 ML | scikit-learn（KNN / RF / 决策树 / GBDT / SVM / KMeans / 回归） |
| 向量检索 | FAISS + sentence-transformers（BGE-large-zh） |
| LLM | DeepSeek（OpenAI 兼容，可换任意兼容后端） |

## 二、系统架构与设计思想

### 2.1 分层架构

```
┌──────────────────────────────────────────────┐
│ 前端 React（40+ 工具页面 · 科技风 · 气泡网格主页）│
├──────────────────────────────────────────────┤
│ 33 个 Router（工具 API + Agent API + Robot API）│
├──────────────────────────────────────────────┤
│ AgentLoop 编排层（感知→规划→执行→反思→输出→记忆） │
│   意图路由 / 技能注册 / 计划缓存 / 记忆 / 反思     │
├──────────────────────────────────────────────┤
│ 工作流引擎（DAG 拓扑执行）+ 工具注册表（43 工具）  │
├──────────────────────────────────────────────┤
│ 服务层（LLM 网关 · 本地模型 · 嵌入 · 音频）        │
└──────────────────────────────────────────────┘
```

### 2.2 核心设计思想

1. **成本分层**：只有「大脑」是大模型，路由 / 记忆 / 缓存 / 规则校验全部用代码实现。缓存 → 技能 → 向量 → LLM 层层拦截，LLM 只在最后兜底。
2. **声明式工具**：加工具 = 加一条 schema 数据 + 一个执行函数，规划器、技能、大脑三处自动感知。
3. **优雅降级**：嵌入模型没装、API key 没配、本地模型缺失，都有 fallback 不崩溃。

## 三、核心技术模块

### 3.1 AI Agent 编排层

**六阶段流水线**：`感知 → 规划 → 执行 → 反思 → 输出 → 记忆`。

**设计目标**：在保证任务完成质量的前提下，最小化 LLM 调用次数。

**LLM 预算机制**：用 `LLMBudget` 类硬性限制编排层的 LLM 调用次数（默认 3 次）。工具执行器内部的 LLM 调用是业务开销，不计入预算。

**分层规划**（从 0 到 1 次 LLM 调用）：

| 优先级 | 机制 | LLM 成本 |
|---|---|---|
| ① | 计划缓存精确匹配（MD5） | 0 |
| ② | 技能匹配（名称/别名/向量） | 0 |
| ③ | 计划缓存向量相似（FAISS） | 0 |
| ④ | 大脑 LLM 判断（chat/single_tool/skill/workflow） | 1 |

**反思自愈机制**：执行失败后先跑规则校验（0 LLM，检查 tool_error / empty_output / json_malformed / truncated_output 等 9 类规则），只有格式类错误才允许 LLM 修复一次，修不好就降级输出成功部分，而不是整段失败。

### 3.2 意图路由（0 LLM 快路径）

入口先走零 LLM 快路径，命中即同步返回，不启动 Agent 循环：

```
关键词正则直达（17 类工具）→ 问候语识别 → 技能精确命中
  → multi-tool 模型把关（≥0.7 判多步骤）→ 单意图本地模型 + 正则提取参数
```

只有全部 miss 才进入 AgentLoop 后台循环（前端轮询 turn_id 状态）。

### 3.3 工作流引擎（DAG）

**数据结构**：plan = `{ nodes[], edges[] }`，node 指定 tool，edge 的 `fromOutput` 指定数据流转字段。

**执行模型**：DAG 拓扑排序 + 线程池并发。计算入度 → 入度 0 的节点入就绪队列 → `ThreadPoolExecutor(4)` 并发执行 → 按边串联数据（`fromOutput` 指定传递字段，否则按回退链自动找 text）。

**AI 自动编排**：LLM 根据工具清单（id/inputs/outputs）把自然语言编排成 JSON plan，校验每个节点 tool 合法。

**前端可视化**：DAG 画布完全手写（未用 react-flow），节点绝对定位 + SVG 贝塞尔连线 + 自实现拓扑分层布局。

### 3.4 技能系统（Skill）

**「文件夹即真相源」**：技能 = `skill.json`（元数据）+ `prompt.md`（方法论）+ `plan.json`（默认流程）。

| 类型 | 定义 | 命中行为 |
|---|---|---|
| 流程型 | 有 plan.json | 直接执行默认流程，0 LLM |
| 知识型 | 只有方法论 | 注入大脑 prompt，由大脑自定工具 |

匹配通道：名称/别名/触发词精确 → 描述向量相似（FAISS）→ 交给大脑。用户可从前端可视化创建自定义技能。

### 3.5 定时智能体（cron）

把已保存的工作流挂到 APScheduler 的 `CronTrigger`（daily/weekly/monthly），无人值守自动执行。支持 `{今天}{上周一}` 等模板变量，历史保留 20 条，重启自动恢复调度。

### 3.6 记忆系统（三层）

| 层 | 存储 | 用途 |
|---|---|---|
| 会话记忆 | agent_sessions + agent_messages | 上下文、追问暂存 |
| 实体记忆 | agent_entities | 用户偏好（负责人/语言/风格），正则 + LLM 双路抽取 |
| 计划缓存 | agent_plan_cache + FAISS | 相似任务复用历史方案 |

## 四、算法与模型

### 4.1 深度学习模型（PyTorch + DistilBERT，MPS 加速）

| 模型 | 类别数 | 用途 |
|---|---|---|
| 意图分类器 | 35 类 | 判断用户想用哪个工具 |
| 多步骤检测器 | 2 类 | 判断单步骤 or 多步骤 |
| 情感分类器 | 3 类 | 情感分析 |

训练脚本在根目录，数据在 CSV，80/20 分层切分。类别从 `labels.txt` 自动读，加新工具只需重训练。

### 4.2 FCN 离职风险预测（本项目的 ML 亮点）

**业务场景**：HR 仪表盘给员工打离职风险分（低/中/高），提前介入留人。

**算法设计**：
- 网络结构：全连接 `14 → 64 → 32 → 1`，ReLU + BatchNorm + Dropout，Sigmoid 输出 0~1 离职概率
- 输入特征 9 个：工龄 / 薪资 / 最近加薪幅度 / 绩效 / 加班时长 / 距上次晋升月数 / 部门（one-hot）/ 年龄 / 考勤异常
- 损失：`BCEWithLogitsLoss(pos_weight)` 处理类别不平衡
- 优化器：AdamW + weight_decay，早停（验证集 AUC）

**为什么用 FCN 替代 SVM**：FCN 能自动学习特征间的非线性交互（如「高绩效 + 长期未晋升 → 高离职风险」这类组合信号），这是线性/浅层模型抓不住的。

**效果**：test AUC 0.73，优于 SVM 基线（0.72）和逻辑回归（0.70）；「高绩效 + 低加薪 + 120 月未晋升 + 高加班」的样本预测离职概率 96%。

### 4.3 经典 ML 模型（scikit-learn）

| 模型 | 算法 | 用途 |
|---|---|---|
| 水果识别 | KNN | 4 类水果 |
| 垃圾邮件检测 | RandomForest | ham/spam |
| 任务优先级 | DecisionTree | 可解释 if-then 规则 |
| 延期风险 | GradientBoosting | 高/中/低风险 |
| 异常员工识别 | KMeans + PCA | 无监督离群检测 |
| 股票预测 | LinearRegression + LogisticRegression | 次日收盘价/涨跌 |

### 4.4 RAG 与向量检索

- 嵌入模型 `BAAI/bge-large-zh-v1.5`（全局共享加载，1.3GB）
- RAG 知识库：文档切片 → FAISS 索引 → top_k 检索问答
- 计划缓存：独立 FAISS 索引，MD5 精确短路 + 向量相似（cos ≥ 0.90），LRU 淘汰

## 五、技术难点与工程实践

1. **LLM 成本控制**：缓存/技能/正则/本地模型四层拦截，`LLMBudget` 硬限编排层调用次数，一个「记录会议→提取待办」的请求，编排层可能只花 1 次 LLM 调用（最后的润色）。
2. **工具抽象统一**：声明式 schema（`id/inputs/outputs/config_schema`）+ 执行器函数，规划器/技能/大脑三处复用同一份元数据。
3. **反思自愈**：规则校验优先（免费），LLM 只修格式类错误，修不好降级而非整段失败。
4. **安全**：计算器用 AST 白名单安全 eval，拒绝任意代码注入。
5. **类别不平衡**：SVM 用 class_weight、FCN 用 pos_weight，评估以 AUC/PR-AUC 为主。
6. **macOS 环境坑**：XGBoost 与 PyTorch 存在 OpenMP 库冲突（同进程加载会段错误），延期风险改用 sklearn 原生 GradientBoosting 规避；模型推理用 Apple MPS 加速。
